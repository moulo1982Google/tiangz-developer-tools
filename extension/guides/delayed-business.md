# 延迟业务：登记任务，现在返回，到期再处理

不要写 `await sleep(工期)` 再升级建筑。把业务拆成“开始”和“到期”两个方法，中间不保留等待时间的调用栈。DB、RPC、锁等结果等待仍允许；禁止的是用 await 等时间。

## 在插件里怎么用

1. 在 `tiangz.timer.time-wait-forbidden` 错误处按 `Ctrl+.`，选择“查看延迟业务范式”或“生成定时器方法骨架”。命令面板也提供这两个入口。
2. 骨架打开为未保存的 TypeScript 草稿，不修改源文件、不搬动任何语句，也不会消除原来的报错。先替换所有者和导入，再将字段放 Model、方法放已有 Hotfix System。处理命名冲突，禁止重复绑定 System。
3. 骨架中的到期方法故意抛出 TODO 错误，必须补全结算和失败恢复后才能使用。它不自动实现扣费、持久化、幂等事务或玩家通知。

## 按这五步组织业务

| 步骤 | 写在哪里 | 需要做什么 |
|---|---|---|
| 定义任务 | Model Component/Entity/Scene | 保存任务ID、参数、状态、代次、墙钟截止时间；TimerId仅运行时保存 |
| 开始 | Hotfix领域方法 | 校验/幂等受理，记录任务，登记 `this.NewOnceTimer(ms, "OnDelayDue", revision)`，立即返回 |
| 到期 | 同一所有者Hotfix方法 | 校验任务仍有效、代次匹配、已到截止时间，再幂等结算 |
| 取消/重排 | Hotfix领域方法 | 先让旧代次失效，再 `CancelTimer`；明确取消与结算冲突的规则 |
| 恢复 | 显式恢复入口 | 读取持久任务，按剩余时间重新登记；已经到期也走同一结算入口，不重复扣费 |

Handler 只做薄适配，回复“已受理/截止时间”；到期由领域方法发布完成通知。不要假设请求会挂着直到升级完成。

## 不能漏掉的边界

- 回调传任务ID/代次等小参数，不保存请求对象、Session、闭包或旧 Hotfix 函数。方法名在触发时解析当前实现。
- 所有者销毁会清理 Timer，但不会替你完成持久业务。离线仍应推进的任务要有重登恢复或离线调度策略。
- TimerId 不入库。恢复截止时间用服务器墙钟，不能跨进程保存单调时钟值；到期重新检查时间，应对时钟校正。
- `CancelTimer` 不能撤回已经执行的效果；代次只能挡住旧回调，不能代替持久幂等。数据库调用返回后仍要重新核对状态；跨重启、重试的效果用稳定任务ID及事务/幂等记录保证。
- 到期失败不会自动完成，也不要通过 sleep 重试。显式记录失败/待重试状态，登记重试 Timer，设置上限并处理结果未知。
- 任务创建时决定哪些配置值固化（例如工期和价格），哪些到期时读取。代码和配置原子切换不替你迁移已经受理的业务任务。
- 周期事件使用 `NewRepeatedTimer`；需要串行且含异步结果等待的周期任务可在完成后重挂一次性 Timer。多个任务不要共用草稿中这个单任务槽，大量任务用最近到期 Timer 合并调度。
- 新增 Model 字段或稳定方法形状，要走正式 codegen/完整构建和 Process 重启。这个范式不改变帧间热更安全条件，也不保证所有 DB/RPC 在途任务能立即排空。
